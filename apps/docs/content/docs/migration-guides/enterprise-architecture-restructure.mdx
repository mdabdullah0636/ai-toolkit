title: Enterprise Architecture Restructure

---

This release restructures the AI TOOLKIT repository into a domain-based
monorepo. **There are no public API changes** — package names, exports, and
semver contracts are unchanged. Existing user code keeps working as-is; this is
a drop-in upgrade.

## Recommended Migration Process

1. Upgrade the AI TOOLKIT packages you depend on to the latest version:

   ```sh
   pnpm up ai @ai-toolkit/provider-utils @ai-toolkit/*
   pnpm install
   ```

2. No code changes are required. If you pinned internal monorepo paths
   (e.g. workspace `file:` links to `packages/ai` or `packages/openai`),
   update them to the new locations listed below.
3. Run your test suite and type checker to verify everything still resolves.
4. Commit your changes.

## No breaking changes for users

| Concern                                       | Status          |
| --------------------------------------------- | --------------- |
| Package names (`ai`, `@ai-toolkit/openai`, …) | Unchanged       |
| Public exports / APIs                         | Unchanged       |
| Package versions                              | Patch bump only |
| Import paths                                  | Unchanged       |

## New repository structure (for contributors & advanced users)

The `packages/` directory is now organized into domain buckets instead of
being flat. Internal cross-package imports already resolve via the package
names, so most consumers are unaffected.

```text
packages/
├── core/
│   ├── ai/                 # the main `ai` package
│   ├── provider-utils/     # shared provider utilities (@ai-toolkit/provider-utils)
│   └── runtime/            # runtime-neutral contracts & capability metadata
├── providers/              # all AI provider implementations
│   ├── openai/  anthropic/  google/  groq/  ... (33 providers)
├── adapters/               # framework UI adapters
│   ├── react/  rsc/  svelte/  vue/  angular/
├── special/
│   ├── gateway/  khulnasoft/
├── validation/
│   ├── provider/  valibot/  capabilities/
├── mcp/                    # MCP core + server tooling (single package)
├── infrastructure/
│   └── test-server/
├── codemod/  devtools/  langchain/  llamaindex/   # (top-level tooling)
```

### Moved packages (reference only)

If you previously referenced packages by their repository-relative path, update
to the new location:

| Before                                                    | After                                  |
| --------------------------------------------------------- | -------------------------------------- |
| `packages/ai/`                                            | `packages/core/ai/`                    |
| `packages/provider-utils/`                                | `packages/core/provider-utils/`        |
| `packages/<provider>/`                                    | `packages/providers/<provider>/`       |
| `packages/react/` (and `svelte`, `vue`, `angular`, `rsc`) | `packages/adapters/<name>/`            |
| `packages/gateway/`                                       | `packages/special/gateway/`            |
| `packages/khulnasoft/`                                    | `packages/special/khulnasoft/`         |
| `packages/provider/`                                      | `packages/validation/provider/`        |
| `packages/valibot/`                                       | `packages/validation/valibot/`         |
| `packages/test-server/`                                   | `packages/infrastructure/test-server/` |

## Examples reorganization

The `examples/` directory is now grouped into categorized subdirectories:

```text
examples/
├── 01-foundations/             # core SDK concepts, no framework
├── 02-framework-integration/   # Next.js, React, Angular, Vue, Nuxt, Nest, LangChain
├── 03-integrations/            # providers, observability, security, MCP
├── 04-tools/                   # playgrounds & developer tooling
└── registry.json               # machine-readable example index
```

Each example now includes an `example.json` describing its category, framework,
primary provider, and tags. Browse them via `examples/registry.json`, or
discover examples programmatically:

```sh
node tools/scripts/inventory.mjs
```
